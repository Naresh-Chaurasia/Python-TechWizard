== Slide 3 — The "USB-C for AI"

* MCP (Model Context Protocol) is a standard protocol for connecting AI agents to enterprise tools, data, and systems
* Works like USB-C → one interface for everything

* *Before MCP*
* Custom integrations required for every tool
* Fragile and expensive

* *With MCP*
* Universal interface for all tools (GitHub, DB, APIs, filesystem)
* No custom glue code

* *Enterprise Benefit*
* Plug new AI models or tools without rebuilding integrations

* MCP eliminates integration sprawl and simplifies architecture

== Slide 4 — AI That Talks to Your Tools

== Slide 5 — MCP Architecture

* *Flow*
* Host Application → IDE / Chat App
* MCP Client → inside host
* Protocol Layer → JSON-RPC communication
* MCP Server → exposes tools
* External Systems → GitHub, DB, APIs

* *Definitions*
* Host → where AI runs (VS Code, Cursor)
* Client → sends/receives requests
* Protocol → standard communication layer
* Server → exposes capabilities

== Slide 6 — How MCP Works

* AI extension acts as MCP Client
* Connects to multiple MCP Servers

* *Flow*
* VS Code
* AI Extension (Continue / Cursor / Claude)
* MCP Client
* MCP Server (GitHub / Filesystem / DB)

* *Key Idea*
* Swap tools or models without changing workflow

== Slide 10 — Step 2: Install GitHub MCP Server

* Run using npx

[source,bash]
----
npx -y @modelcontextprotocol/server-github
----

* *Capabilities*
* Read repositories
* Search code
* Create issues
* Manage pull requests

== Slide 11 — Step 3: Configure MCP

[source,json]
----
{
  "mcpServers": {
    "github": {
      "command": "npx",
      "args": ["-y", "@modelcontextprotocol/server-github"],
      "env": {
        "GITHUB_TOKEN": "your_token_here"
      }
    }
  }
}
----

* *Key Fields*
* command → runtime
* args → package
* env → secrets
* mcpServers → multiple servers config

== Slide 12 — Step 4: GitHub Token

* Go to GitHub Settings → Developer Settings
* Create Personal Access Token (PAT)

* *Permissions*
* repo
* read:org
* workflow

* Add token to MCP config and restart extension
